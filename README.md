# Лабораторная работа 11: CI/CD с GitHub Actions

Мини-проект демонстрирует простой CI/CD-процесс для web-страницы с формой. Пользователь вводит `Name` и `Email`, отправляет форму и получает сообщение об успехе. При попытке отправить пустую форму показывается ошибка.

## Технологии

- HTML, CSS и JavaScript для интерфейса.
- Node.js для локального web-сервера.
- Jest и Selenium WebDriver для UI-тестов.
- GitHub Actions для автоматического тестирования и публикации в GitHub Pages.

## Локальный запуск

Потребуются Node.js 20 или новее и Mozilla Firefox. В GitHub Actions Firefox устанавливается автоматически тем же workflow.

```bash
npm install
npm start
```

После запуска страница доступна по адресу `http://localhost:3000`.

## Запуск тестов

```bash
npm test
```

Тесты автоматически запускают локальный Node.js-сервер и открывают страницу в headless Firefox через Selenium. Реализованы четыре UI-теста:

1. Страница успешно открывается.
2. Форма и её основные поля существуют.
3. Пустая форма показывает сообщение об ошибке.
4. Корректно заполненная форма показывает сообщение об успешной отправке.

## CI/CD

Workflow находится в `.github/workflows/ci.yml`.

- При каждом `push` и `pull_request` GitHub Actions устанавливает зависимости и выполняет `npm test`.
- Если хотя бы один тест не проходит, job завершается с ошибкой, поэтому workflow тоже считается упавшим.
- Job публикации зависит от успешного job тестирования.
- GitHub Pages публикуется только после успешного `push` в ветку `main`.

Для первой публикации в настройках репозитория GitHub нужно выбрать источник Pages: **GitHub Actions**.

## Работа с ветками

- `main` содержит стабильную версию проекта и является единственной веткой, из которой выполняется deployment.
- `dev` используется для разработки новых возможностей. Из неё создаётся pull request в `main`, а CI проверяет изменения до объединения.
- `fix` используется для исправлений ошибок. После проверки исправление также объединяется в `main` через pull request.

Пример учебного процесса:

```bash
git checkout -b dev
# разработка и commit
git push -u origin dev
# pull request: dev -> main
```

После merge в `main` тесты запускаются повторно, и при успешном результате новая страница автоматически публикуется в GitHub Pages.
